## 2. Сценарій перевірок (усі кроки — журнал з exit code)

| ID | Перевірка | PASS | FAIL |
| --- | --- | --- | --- |
| T0 | `static-clean-install.ps1`, `run-all.ps1` на хості | exit 0 | інакше |
| T1 | `clean-install.ps1 -TestHost …` — етапи 4.0–4.7 і smoke | `CLEAN INSTALL PASS`, exit 0 | будь-який STOP |
| T2 | Windows Services: обидві служби `Automatic`, `Running`, облікові записи `NT SERVICE\integrity-v2-*`, WinSW = SHA `05b82d46…` | так | інакше |
| T3 | ACL: `C:\srv` (якщо створювався) — `O:BA D:PAI`, наявний — без змін; `C:\srv\integrity-v2` і підкаталоги — як у плані 4.1/4.3; сторонніх записів немає | так | інакше |
| T4 | TLS: `https://<тест-вузол>` — сертифікат Tailscale, перевірка сертифіката **увімкнена** (без `-SkipCertificateCheck`/CERT_NONE) | 200 / 401 як у smoke | помилка TLS |
| T5 | Bootstrap: рівно 1 адміністратор; `auth-schema` робочої БД і фінальної копії PASS; маркер `CLEAN-INIT-OK` | так | інакше |
| T6 | 2FA: вхід адміністратора, код через Mailtrap Sandbox, повторне використання коду відхиляється (ручні S1–S8) | так | інакше |
| T7 | Безпечне завершення: `Stop-V2Service` для backend і Caddy — служба `Stopped`, процесів облікового запису служби 0, дерево процесів завершено; сторонні процеси не зачеплено | так | інакше |
| T8 | Перезапуск ОС → обидві служби стартують, `Assert-V2DataReady` PASS | так | інакше |
| T9 | Примусова помилка на 4.5 (наприклад, пошкоджена БД) → STOP; маркери `CLEAN-INIT-FAILED-*` у `data\` і `CLEAN-INSTALL-FAILED-*` у корені; служби V2 (якщо вже є) зупинено й `Disabled`; backend не стартує | так | старт backend або повторне використання БД |
| T10 | **CI-01:** примусова помилка **після `CLEAN-INIT-OK`** окремо на 4.6, 4.7 і 5 (smoke) → `CLEAN-INIT-OK` → `CLEAN-INIT-REVOKED`, `CLEAN-INIT-FAILED-INSTALL` у `data\`, `CLEAN-INSTALL-FAILED` у корені; обидві служби V2 `Stopped` + `Disabled`; `sc start integrity-v2-backend` → відмова SCM (1058); БД і копії без змін (SHA256 до/після) | так (усі три етапи) | будь-який READY, старт backend або зміна БД |
| T10a | Повторний `clean-install.ps1` поверх наявного кореня/служб (без `-Abort`) → STOP **без змін** наявного встановлення (служби й маркери не чіпаються) | так | будь-яка зміна |
| T11 | `clean-install.ps1 -Abort` після T9/T10 (служби `Disabled`) → служби V2 видалено, процесів V2 0, корінь `…-abandoned-<ts>` з доказами, маркер `CLEAN-INIT-FAILED-ABANDONED`; production-даних немає, автоматичної очистки немає | так | інакше |
| T12 | Повторний Clean Install після `-Abort` (новий корінь) → T1 PASS; дані з `-abandoned` не використано | так | інакше |
| T13 | Якщо на хості є V1 — `Assert-V1Unchanged` PASS після кожного етапу | так | інакше |

**C3 = PASS** лише якщо T0–T12, T10a (і T13, якщо V1 є) = PASS, жодного NOT RUN. Після прогону VM відкочується до знімка.

## 3. Межі

На production-сервері цей сценарій **не виконується**. Git, GitHub, робочі БД — без змін. Налаштування безпеки Windows не змінюються.
