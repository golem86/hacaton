# Підключення Analytics до Dashboard після Survey

## Уже є в коді

- Backend надає `GET /api/index-methodologies/{version}`, `GET /api/assessments/{id}/index?methodology=team-results-demo-0.1`, `GET /api/assessments/{id}/recommendations?methodology=team-results-demo-0.1` і `GET /api/analytics/comparisons?assessment_id={before}&comparison_assessment_id={after}&methodology=team-results-demo-0.1`. Параметр `methodology` обов’язковий для трьох обчислювальних маршрутів. Порівняння другого циклу необов’язкове.
- Маршрути беруть агрегати з чинного `/results` для закритих циклів, перевіряють демонстраційну роль через `X-Role`, приховують малі категорії та не змінюють БД. Обчислювальні маршрути вимагають `INTEGRITY_ANALYTICS_DEMO=1` і окремої синтетичної БД через `INTEGRITY_DB`; прапорець не перевіряє походження записів.
- Відповіді містять `approval_status=proposed`, `synthetic_only=true`, `official=false`, числові або `null` значення та статуси приховування. Порівняння двох циклів повертає `limited_comparability`; рекомендації лишаються пропозиціями для людського рішення. Доменний Tracker ще не має підключеного збереження та HTTP-маршрутів.
- Наявний frontend використовує `/api/assessments`, `/api/assessments/{id}` та `/api/assessments/{id}/results`. Викликів Analytics API і відповідних екранів у поточному frontend немає.

## Що №5 ще має узгодити й інтегрувати

1. Після стабілізації Survey визначити окреме джерело синтетичних даних і спосіб локального ввімкнення деморежиму; не вмикати його на спільній БД або сервері без окремого рішення.
2. Додати клієнтські виклики чотирьох маршрутів із явною версією методики. У UI показувати `proposed` і `synthetic_only`, не називати індекс офіційним. Для `null`, `suppressed`, `insufficient_data` та прихованих категорій показувати пояснення без нуля або похідних чисел.
3. Показувати `limited_comparability` і попередження поруч із динамікою. Узгодити незмінні версії анкет, каталогу, методики й популяції для кожного циклу, перш ніж трактувати динаміку як надійне порівняння.
4. Обробити `401` (немає/невідома роль), `403` (роль без доступу), `409` (відкритий цикл або несумісні компоненти/ваги), `503` (деморежим вимкнено); також перевірити `404` і `422` за [контрактом](API_CONTRACT.md). `X-Role` — лише демонстраційний механізм, не справжня авторизація.
5. Окремо погодити персональну авторизацію, людське прийняття рекомендацій, збереження Tracker та інтеграцію у Dashboard. Поточні GET-маршрути цього не роблять.
