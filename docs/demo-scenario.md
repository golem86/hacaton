# Сценарій демонстрації: один цикл оцінювання від кодів до звіту

Покроковий сценарій для пункту 2 завдання «Демонстрація проходження оцінювання з цифровими опитувальниками». Відео демонстрації (до 3 хв): https://youtu.be/2qqYt_XbQeE. Його можна повторити в локальному Docker-стеку ([README](../README.md), «Як запустити») або на робочому сервері. Дані лише синтетичні.

## 1. Адміністратор: цикл і коди

1. Увійдіть адміністратором (пароль і код 2FA).
2. «Цикли оцінювання» → **«Новий цикл»**: назва, період, категорії респондентів, поріг групи k (не менше 5) → **«Створити чернетку»**.
3. **«Активувати»** цикл.
4. Блок **«Одноразові коди доступу»**: оберіть категорію й кількість кодів, видайте їх і збережіть через **«Завантажити файл .txt»**. Відкриті коди показуються лише один раз, сервер зберігає тільки їхні хеші. Коди може видавати й відповідальний за коди доступу (роль `data_officer`).
5. Роздайте коди учасникам анонімно, наприклад у конвертах, без списку «хто який код отримав».

## 2. Респондент: анонімна анкета

1. Відкрийте `/survey` у звичайному або приватному вікні. Входу й акаунта не потрібно.
2. Введіть **одноразовий код доступу**, оберіть категорію й підрозділ із довідника.
3. Дайте відповіді на питання анкети й надішліть її. Сервер відповідає «прийнято».
4. Повторне використання того самого коду відхиляється.

Анкета зберігається без коду, акаунта й точного часу подання ([anonymity.md](anonymity.md)).

## 3. Адміністратор: участь і закриття

1. Блок **«Участь»** показує, скільки кодів використано. Поки цикл відкритий, результатів немає: інакше нову анкету можна було б розпізнати за зміною середніх.
2. **«Закрити цикл»**. Лише після цього з'являються результати.

## 4. Керівник: результати й висновки

1. **«Огляд»**: Integrity Index, зона й рівень зрілості, зміна до попереднього циклу, радар C1–C7, сильні сторони й проблемні зони ([dashboard-example.md](dashboard-example.md)). Групи, менші за k, приховано.
2. **«Аналітика»**: бали компонентів, порівняння категорій, таблиця «Самооцінка vs об'єктивні показники» ([objective-comparison-example.md](objective-comparison-example.md)).
3. Пропозиції рекомендацій з поясненням правила й значень, що їх спричинили ([methodology.md](methodology.md), розділ 7).

## 5. Від рекомендацій до дій

1. **«Трекер рекомендацій»**: **«Прийняти»** або **«Відхилити»** пропозицію, призначити відповідальну посаду й строк.
2. Статуси «прийнято → в роботі → виконано → перевірено». Виконання перевіряється наступним циклом.

## 6. Звіти

1. **«Звіти»** → «Звіти за циклами»: PDF або XLSX за закритим циклом.
2. Необов'язково: кнопки «(ШІ)» готують чернетку тексту з агрегатів локальною моделлю. На CPU це займає 1,5–4 хв, а кожне число в тексті звіряється з даними ([LOCAL_LM.md](LOCAL_LM.md)).
3. «Журнал дій» показує, хто й що робив, але без змісту анонімних відповідей.

## 7. Користувач: особистий кабінет

Звичайний користувач (роль `user`) після входу з 2FA бачить «Мій кабінет»:
- особисті тестування з чернетками й історією;
- персональну статистику;
- «Результати підрозділу» — бали свого підрозділу за закритий цикл.

Якщо в циклі хоча б одна група «категорія × підрозділ» менша за k, результати підрозділів за цей цикл приховано ([USER_UNIT_RESULTS_API_PROPOSAL.md](USER_UNIT_RESULTS_API_PROPOSAL.md)).

Готові синтетичні цикли для показу (150 анкет і цикл для «Результатів підрозділу») створює `app.demo_cycle` ([DEMO_DATA.md](DEMO_DATA.md)).
