# Правила безпеки Integrity Management Dashboard

Актуальне завдання вимагає синтетичних демонстраційних даних без персональних, службових та інших відомостей з обмеженим доступом. Дані оцінювання не призначені для оцінки або покарання окремих керівників чи респондентів.

## Анонімність і агрегування

- У сховищі анонімних відповідей не повинно бути прямих ідентифікаторів респондента або зв’язку з обліковим записом. Дані про відповідальних за інституційне оцінювання зберігаються окремо від анонімних відповідей.
- Мінімальний розмір групи налаштовується для циклу оцінювання. Сервер приховує агрегат і його деталізацію, якщо кількість відповідей у конкретному зрізі менша за поріг. Це правило поширюється на Dashboard, порівняння, звіти й експорт.
- Комбінації фільтрів і порівняння сусідніх агрегатів не повинні дозволяти відновити відповідь малої групи. Реалізоване правило (`backend/app/anonymity.py`): первинне приховування груп < k і вторинне — сума прихованих груп у межах кожного відомого підсумку дорівнює 0 або не менша за k. Розбивка участі для відкритого оцінювання не показується. Нові аналітичні маршрути мають використовувати ту саму функцію для кожного підсумку, який вони розкривають.
- Журнал дій не містить тексту анонімних відповідей та ідентифікаторів, які дають змогу пов’язати відповідь із респондентом.

## Доступ і конфігурація

- Ролі для учасника оцінювання, відповідальної особи, аналітика й керівника є попередньою моделлю. Команда має затвердити матрицю дій та область видимості кожної ролі до реалізації авторизації.
- У прототипі роль передається заголовком `X-Role` **лише для демо**. Це не автентифікація, і так розгортати не можна: у реальній системі роль надходить із відомчої системи входу, а заголовок вимикається. Поточну матрицю доступу наведено в `docs/API_CONTRACT.md`.
- Доступ до сирих даних, агрегатів, інституційних підтверджень, рекомендацій і журналу дій потрібно розмежувати на backend. UI не є межею захисту.
- Локальний CORS обмежений адресами frontend. Для розгортання список дозволених джерел треба налаштувати під фактичний домен.
- Не додавати до Git ключі, токени, справжні `.env`, файли SQLite, дампи, журнали чи відповіді. `.gitignore` не захищає вже відстежувані файли.
- Демонстрації, тести й знімки екрана використовують лише штучно сформовані записи. Перед публікацією перевіряти також звіти та експортовані файли.
