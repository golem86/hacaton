# Assessment Manager V2 — локальний контракт

Нові цикли мають стан `draft → open → closed`. Існуючі цикли без `cycle_configs` залишаються сумісними з попереднім `open/closed` Survey API. Створення, активація, видача кодів і закриття вимагають перевіреної адміністративної сесії та CSRF; `X-Role` працює лише в старому development demo-режимі. API не дозволяє змінювати конфігурацію після створення, тому поріг приватності, категорії та версія не змінюються після отримання відповідей.

## API

- `POST /api/assessments`: `{name,description,scope,start_date,end_date?,categories,min_group_size,questionnaire_version:"demo-v1"}` → 201 і цикл у стані `draft`. `min_group_size` 5–1000; категорії тільки `mgmt`, `npp`, `cadets`, `staff` без повторів; дата кінця не раніше початку.
- `POST /api/assessments/{id}/activate`: тільки `draft` → `open`, інакше 409.
- `POST /api/assessments/{id}/tokens?count=1..500&category=cadets&expires_days=1..365`: для нових циклів категорія обов'язкова і має бути дозволеною. Відповідь `{tokens:[...]}` показується тільки при видачі. Старі цикли можуть використовувати маршрут без категорії.
- `POST /api/assessments/{id}/submissions`: новий цикл вимагає `questionnaire_version:"demo-v1"` та збіг категорії з категорією коду; код із минулим строком відхиляється загальним 403. Існуючий payload для старих циклів працює без версії.
- `GET /api/assessments/{id}/participation`: додано `tokens_unused` і `participation_percent`; кількість анкет, невикористаних кодів і відсоток є `null`, коли `responses_total < k`. Інакше `tokens_issued - tokens_unused` розкрив би приховану кількість подань. Для циклу з менш ніж `k` анкетами немає навіть назв груп (`groups: null`); для відкритого циклу розбивка також недоступна.
- `POST /api/assessments/{id}/close`: попередній контракт, тільки `open` → `closed`.

Таблиці `cycle_configs` і `access_token_policies` додаються без перебудови старих таблиць. Схема БД тепер версії 3; при локальній міграції існуючого файлу створюється резервна копія. У release потрібна явна перевірена міграція за `docs/DATABASE_UPGRADE.md`. Це **спільна міграція**, яку координує учасник №5.

## Методика та межі

Поточні 14 питань у `backend/app/seed.py` є демонстраційними твердженнями C1–C7, по два на компонент, з числовою шкалою 1–5. `demo-v1` фіксує саме цей контракт для нових циклів. Перевірений [Додаток В Рекомендацій НУОУ](https://nuou.org.ua/assets/documents/recommendations_transform_dobrochesnist.pdf) містить Анкету 1 для робочої групи (друк. с. 53–59) і Анкету 2 (друк. с. 60–66): її заголовок теж називає робочу групу, тоді як Додаток Г, с. 67, відносить її до особового складу з описовими варіантами відповідей. Наприклад, п. 1 Анкети 1 на друк. с. 53 питає про роль керівника в розбудові доброчесності; п. 1 Анкети 2 на друк. с. 60 — про цінність доброчесності й корпоративної культури. Жодне з 14 seed-тверджень не є дослівною реалізацією цих пунктів. Зіставлення 14 тверджень з C1–C7 наведено в `backend/app/seed.py` (`QUESTIONS`) і [methodology.md](methodology.md), розділ 3.

Автентичні опції потребують нового каталогу варіантів і затвердженого відображення в бали; поточний Index споживає числові середні й фіксовані C1–C7. Без погодження власників методики й Analytics не змінювати цю шкалу або видавати демонстраційний Index за офіційний. Експертна оцінка поки не реалізована: поле `Question.kind="expert"` не створює окремої авторизації, форми, зберігання чи контракту Index. Пропозиція: після узгодження додати окрему версійовану expert-анкету, роль/допуск експерта, ізольований endpoint подання та явний статус `expert_data_unavailable` у downstream контракті. Не генерувати експертні результати з seed.

## Анонімність

`access_token_policies` містить лише кодову категорію і строк дії. Немає посилання на `response_sets`, ідентичності, часу подання або тексту відповідей. Відповіді, погашення коду та статус циклу перевіряються в одній транзакції; паралельне подання одного коду має лише один 201. Тест паралельного `close`/`submit` перевіряє, що результат коду і анкети узгоджений та після підтвердженого закриття наступне подання відхиляється. Production журнали проксі залишаються окремим release gate.
